# Quality Gates

Use only gates relevant to the project and change. Identify the real commands from the repository.

## Before completion

- [ ] Requirement/acceptance criteria addressed.
- [ ] Diff is scoped; unrelated edits preserved.
- [ ] Names and responsibilities are clear.
- [ ] No accidental duplicate implementation or unnecessary dependency.
- [ ] Types, validation, errors, and security boundaries considered.
- [ ] Frontend/backend contracts match where applicable.
- [ ] Relevant tests, lint, typecheck, and/or build run where available.
- [ ] UI states, accessibility, and responsive behavior checked where relevant.
- [ ] Documentation and `todo-list.md` updated if status/context changed.
- [ ] Remaining TODOs, assumptions, and unverified areas reported.

## Honest status

Report each check as `passed`, `failed`, `skipped`, `blocked`, or `not run`. Do not imply a skipped check passed. A successful compile does not prove business correctness, security, or end-to-end integration.
